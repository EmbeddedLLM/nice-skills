# Internal communication formats

Use the organization's supplied template and vocabulary first. Work from pasted notes or local source files; a chat, mail, or company-directory integration is optional.

| Format | Useful structure |
| --- | --- |
| Team update | Reporting period; progress, plans, and problems. Separate completed work from future commitments. |
| Leadership update | Outcome or decision needed; supporting evidence; material risk; requested action with known owner/date. |
| Newsletter | Consequential changes grouped by reader interest; who is affected and source links. |
| FAQ | Reader question; direct answer; authoritative source; unresolved policy questions explicitly marked. |
| Incident update | Current status, confirmed impact, mitigation, available workaround, and established next update time. Separate suspected causes from confirmed ones. |

Preserve time zones, measurement periods, and the distinction between targets and results. Select information for relevance, not message popularity or author seniority. Do not invent policies, owners, deadlines, links, or an official voice the user has not authorized.

Example: “Draft Friday's update: migration completed; latency review pending; next trial Monday.” Record the migration as completed, the review as unresolved, and Monday's trial as planned. Do not assert the migration improved latency.

Before delivery, check the first paragraph answers the audience's main question and any requested action is clear. Deliver a draft unless sending or publishing is separately authorized.
