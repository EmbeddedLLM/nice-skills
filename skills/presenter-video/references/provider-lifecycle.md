# Provider lifecycle

The local `scripts/provider_job.py` ledger is a reusable lifecycle primitive, not a live API integration. Use a separate ledger per pilot or audio segment, and a shared authorized budget across those ledgers. Allocate per-segment limits so their sum cannot exceed that budget. Money uses integer minor units, not floating-point estimates. `cost_per_attempt` must conservatively bound the provider charge; if no bound is available, stop for a revised plan before submitting.

An adapter implements `ensure_ready()` (credentials/configuration validation without paid I/O), `submit(request, idempotency_key)` (returns a task ID), `lookup(idempotency_key)` (recover a possibly accepted submission), and `poll(task_id)` (returns `pending`, `succeeded`, or `failed`). Credentials stay in the environment or secret store. The sanitized request includes provider/model/version/region, local asset hashes, authorized units, and generation parameters; omit secrets, private URLs, and raw personal assets from the ledger. Record selected output separately in the Lanshu job artifacts after downloading and verifying it.

Call `advance(ledger_path, sanitized_request, adapter, max_attempts=3, budget=300, cost_per_attempt=100)` once per bounded polling interval. These illustrative limits are not prices or user approval. It persists submission intent before the call and records the returned ID immediately. Restarting polls the existing task; failed polling retains that ID. Terminal failure permits another attempt only within the original ceiling. Successful completion is reused. It does not silently raise limits or retry uncertain submissions.

If submission times out or the process dies before saving an ID, the next call reconciles using the saved key. A provider without lookup support must report unresolved and require manual reconciliation; returning no match never authorizes resubmission. Even failed/unknown attempts keep their full cost reservation. Request or limit changes are rejected on an existing ledger. Concurrent processes serialize on a local POSIX file lock; use a durable transactional store instead on distributed workers/network filesystems.

The mock tests exercise missing credentials, crash/timeout recovery, duplicate prevention, changed requests, attempt ceilings, and budget ceilings. They make no claim about provider quality, real billing, remote retention, or successful lip-sync. Record whether a live paid pilot was separately authorized and run.
